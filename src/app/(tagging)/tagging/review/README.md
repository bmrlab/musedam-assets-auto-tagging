## 概述

AI打标审核页面是MuseDAM自动打标系统的核心功能之一，用于审核AI预测的标签结果。该页面允许用户查看、筛选和管理AI为资产推荐的标签。

## 功能特性

### 📊 统计面板

- **全部状态统计**: 显示所有审核项的总数
- **待审核**: 需要人工确认的标签预测
- **已采纳**: 用户确认正确的标签
- **已调整**: 用户标记为不准确的标签
- **未匹配**: 无法匹配到标签体系的预测

### 🔍 筛选功能

- **状态筛选**: 按审核状态过滤 (全部/待审核/已采纳/已调整)
- **置信度筛选**: 按AI预测的置信度过滤
  - 精准 (≥80%): 高置信度预测
  - 平衡 (60-79%): 中等置信度预测
  - 宽泛 (<60%): 低置信度预测
- **时间筛选**: 按打标发起时间过滤 (TODO)
- **搜索**: 支持按文件名、描述和路径搜索

### 📋 资产展示

- **资产信息**: 显示文件名、路径、创建时间等基本信息
- **现有标签**: 显示资产当前已有的标签
- **AI推荐标签**: 展示AI预测的标签及其详细信息
  - 标签路径: 完整的层级路径 (如: 媒体类型 > 图片 > 产品图)
  - 置信度: 以百分比和颜色条显示
  - 置信度等级: 精准/平衡/宽泛的文字标识
  - 审核状态: 当前的审核状态

### ⚙️ 操作功能

- **单个审核**: 对每个标签预测进行确认或拒绝 (TODO)
- **批量操作**: 批量采纳或拒绝标签 (TODO)

## 审核内容筛选与操作范围

审核内容支持全部、仅标签、仅特征，以及开通元数据字段后的仅字段。类型条件同时作用于服务端素材计数和分页；切换类型会清空跨页选择与临时手工添加项，避免把上个范围的选择带入批量操作。

仅标签／仅特征的单素材和批量操作统一走 `reviewScopedAssetsAction`，服务端按当前团队、素材及可见审核项 ID 重新查询待审核记录，不处理隐藏的元数据结果。标签与特征历史上共用审核记录：分开审核时使用现有空标签路径记录承载特征的独立状态，并沿用 `featureReview` 快照；特征采纳可附带其关联标签，但不会采纳通用标签预测。特征快照附带 scoped 与本次 startsAt，后续重跑不继承上一次单独审核的完成状态。不需要数据库迁移。

「未匹配」按当前审核内容类型判断；「全部内容」要求本次参与处理的各类型都没有有效结果。它从每份素材最近一次正式任务的原始结果查询，不把 rejected 审核记录改成未匹配，也不创建可添加／删除的审核项。最近一次任务仍在排队、处理中或失败时不回看旧的空结果；测试任务、标签树任务、已删除源素材及不完整的特征决策不作为未匹配证据。常规审核状态继续查询审核记录。

新任务在 result.outputTypes 中记录本次实际参与处理的类型：元数据没有可填字段时不会标为参与处理，单纯关闭某类输出也不构成未匹配。历史元数据任务按 metadataPredictions 键兼容，历史标签按来源预测对象（关闭输出时为空数组）兼容，历史特征按已完成的识别诊断或实际特征结果对象兼容；缺少执行类型证据的历史任务不猜测为未匹配。无需迁移或重写历史记录。新任务的完整类型记录需要对应 web／worker 升级到本版本。

字段候选（effective=false）不算有效字段结果；布尔 false 的有效预测仍算匹配。特征采用已有审核置信度、人物原始相似度和商品来源区域规则，数组结果优先于旧 bestMatch；只读 PostgreSQL CTE 样例会与 getReviewFeatures 校验一致性。未匹配页不显示置信度与匹配来源筛选，因为没有有效结果可以按这两项筛选；保留素材搜索和时间筛选。

2026-11-10 修复设置确认弹窗：开通元数据时明确显示「开启／关闭 按标签体系打标」；字段填写按钮分别为「确认开启／确认关闭」，取消不触发保存。

## 数据流程

### 1. 标签预测生成

```
AssetObject → AI预测 → TaggingQueueItem → TaggingAuditItem
```

1. 资产对象被提交到打标队列
2. AI分析资产的基本信息、路径结构和内容
3. 生成多个标签预测，每个预测包含:
   - 信息源 (basicInfo/materializedPath/contentAnalysis)
   - 标签路径
   - 置信度分数
   - 叶子标签ID

### 2. 审核项创建

每个AI预测会创建一个`TaggingAuditItem`记录：

- `confidence`: 0-1之间的置信度分数
- `tagPath`: JSON数组，存储完整标签路径
- `leafTagId`: 最终标签的数据库ID
- `status`: pending/approved/rejected
- `queueItemId`: 关联的队列项ID

### 3. 按资产聚合显示

审核页面按`AssetObject`分组显示所有相关的审核项，方便用户一次性审核一个资产的所有标签预测。

## 置信度评分系统

### 精准区间 (0.80-1.00) - 蓝色

- 直接匹配关键词
- 上下文明确支持
- 无歧义性

### 平衡区间 (0.70-0.79) - 绿色

- 合理推断得出
- 较强支持证据
- 轻微歧义但最优

### 宽泛区间 (0.60-0.69) - 黄色/橙色

- 弱关联推测
- 有限证据支持
- 存在其他可能选择

### 低置信度 (<0.60) - 红色

- 几乎无关联
- 高度歧义
- 信息严重不足

## 使用建议

1. **优先审核高置信度预测**: 从精准区间开始审核
2. **关注批量相似预测**: 相同类型的文件可能有相似的标签模式
3. **验证标签体系匹配**: 确保预测的标签路径在当前标签体系中存在
4. **定期清理低质量预测**: 拒绝明显错误的预测以改善AI模型
